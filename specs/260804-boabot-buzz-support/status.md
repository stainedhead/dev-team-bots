### Phase G — Process-singleton lock (OQ-1)
- [x] G1 — `internal/infrastructure/buzz/lock.go`: `AcquireLock(path)`/`Lock.Release()`, a dependency-free, stdlib-only OQ-1 process-singleton lock keyed on the agent's derived pubkey (never the raw nsec — this package never writes secret key material to disk anywhere). `os.OpenFile(O_CREATE|O_EXCL)` writes our own PID; a second acquirer against the same path reads the existing PID and checks liveness portably (Unix: `os.FindProcess` + `Signal(0)`; Windows: `os.FindProcess`'s own open-handle failure *is* the check, since `Signal` there only supports `os.Kill`) — a live holder yields `ErrAlreadyRunning` (wrapped, `errors.Is`-checkable); a dead holder's lock file is removed and creation retried, so a crash-abandoned lock never permanently wedges future starts. A zero-byte lock file (the realistic SIGKILL-mid-write artifact, landing between `O_CREATE` and the PID `WriteString`) is treated as pid 0 — never alive — and reclaimed the same way; non-empty-but-unparseable content is treated conservatively as held (fails closed, cannot prove abandonment). Wired into `Monitor.Start` (`monitor.go`) as a real gate on the existing lifecycle method: `Config.LockDir` set + `AcquireLock` failing ⇒ `Start` logs a clear FR-031-tagged error naming the contended pubkey and returns `nil` without launching `run`/touching the relay at all — every other channel/bot in the process is unaffected (mirrors `credentials.go`'s fail-fast-without-crashing precedent). `Config.LockDir` empty (the zero value, until Phase H's `cmd/boabot/main.go` wiring sets it) leaves Phase F's `Start` behaviour completely unchanged but logs a `WARN` that FR-031 protection is inactive, so a missed H2 wiring step is greppable at runtime, not just discoverable by reading source; `LockDir` set with `AgentPubKeyHex` empty is refused outright (would collapse every identity onto one `buzz-.lock` file). `Monitor.Stop` (`presence.go`) releases the lock in the same shutdown sequence as the F15 offline-presence publish, so a clean restart of the same process/identity is never wedged by its own prior run.
