FR-012.

**Critical finding during D1/D3–D8:** `fiatjaf.com/nostr`'s `event.go` (SWAR-optimized JSON-string escaping used by `Sign`/`VerifySignature`) has a genuine, confirmed upstream `unsafe.Pointer` rule-1 violation that `go test -race`'s `checkptr` instrumentation catches non-deterministically as a hard process-aborting `fatal error` whenever an event is signed while any other goroutine is alive — true of essentially every test in this package. **Workaround (verified stable across 5+ full-suite runs, does not weaken actual race detection): `go test -race -gcflags=all=-d=checkptr=0 ./...`.** This flag is now required for every `-race` invocation touching `internal/infrastructure/buzz` (and therefore repo-wide `./...` runs). Full repro history and exact code location in `research.md`; flagged on the manual-verification checklist below for upstream filing since this environment has no outbound issue-tracker access.

`go build ./...`, `go vet ./...`, `golangci-lint run` all pass repo-wide with zero issues. `go test -race -gcflags=all=-d=checkptr=0 ./...` passes repo-wide (verified 3x). Coverage: `internal/domain/buzz.go` 100% of its own statements; `internal/infrastructure/buzz` 89.2% overall, with every function above 70% except `conn.go`'s thin real-library wrapper (0%, by design — covered instead by a `//go:build integration` stub, `conn_integration_test.go`, for Phase I). Full details in `implementation-notes.md`'s new "Phase D" section.
